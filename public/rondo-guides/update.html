01
受け取ったら

新しい版を展開する

届いた圧縮ファイル（rondo-dist）をダブルクリックで展開し、フォルダの場所を控えてください。 いま運用中のRondoフォルダは、まだ触らなくて大丈夫です。

02
まずこれだけ

この依頼文をAIへ渡す

運用中のRondoフォルダを開いているClaude CodeやCodexなどの作業AIへ、下の文章をそのまま渡してください。 かっこの中だけ、あなたの展開先に書き換えます。

AIへの更新適用依頼文 
Rondoの新しい版を受け取りました。展開したフォルダは（ここに展開先の場所を書く）です。

展開した新しい版のフォルダにあるSETUP.md（いま運用中のフォルダの古いSETUP.mdではなく）の「更新の適用」の節を全文読み、その手順どおりに、いま運用中のこのRondoへ新しい版を適用してください。

守ってほしいこと：
- コマンドはすべてあなたが実行し、私には打たせないでください
- 適用の前に、いまのフォルダの控えとデータベースの控えを必ず取ってください
- 私の設定ファイルと原稿は、新しい版のサンプルで上書きしないでください
- テストが全部緑になるまで、本番への反映はしないでください
- 終わったら、健康診断の表示で版番号が新しくなっていることと、管理画面が正常なことを見せてください

作業中は、いま何をしているかと、私が次にすることだけを短く案内してください。
設定と原稿は守られます

あなたが埋めた設定ファイルと、あなたの原稿、読者のデータは更新で上書きされません。手順書がそのように書かれていて、AIはそれに従います。

03
最後の確認

AIと一緒に確認する

AIから完了報告が来たら、次の3点を一緒に確認してください。どれかが欠けていたら、そのまま伝えれば大丈夫です。

  • テストが全部緑だったという報告があること
  • 健康診断の表示に、新しい版番号が出ていること
  • 管理画面のダッシュボードがいつもどおり表示されること

LINE（Lステップ相当の機能）

  • タグ・友だち情報・計測リンク: 押したリンク・ボタン・答えでタグや友だち情報を付け、タグの組み合わせ（AND/OR/NOT）で一斉配信や分岐ができます。リンクは誰が押したかを記録します。手順は SETUP.md §10
  • 複数のシナリオ・分岐・リマインダ: シナリオをいくつでも持て、タグで本文の節を出し分けられます。日付の友だち情報（例: セミナーの日）を起点に「3日前・前日・当日」に送るリマインダも作れます
  • リッチメニュー・流入経路: タグで切り替わるリッチメニュー、どの導線から友だちになったかを数える経路URL（/in/<経路>）を追加しました
  • 1:1トーク・回答フォーム: 友だちとの個別のやり取りを管理画面で読み、返信できます（要対応・未読の絞り込み）。LINE内で答えられるフォームも作れます
  • AI返事（任意）: キーワードで答えられなかった質問に、自分の発信をもとにAIが返します。返金・解約などの話や命に関わる言葉は人に回し、送る前に2段階で検査します。最初は「案を置くだけ」の試運転から始められます。使うにはAIのAPIキーと、プライバシーポリシーへの追記が必要です
  • Lステップからの引っ越し: LステップのCSVからタグ・友だち情報を取り込み、名前で照合した候補を人が確かめて結びます
  • 既知の制限: リッチメニューの自動の付け替え・手で選んだメニュー・タブ切替が同時に重なると、ごくまれに意図と違うメニューが残ることがあります（SETUP.md §10-9 の手順で揃え直せます。後の版で直します）

LINE の画像・動画・分析　LINE で文字以外のメッセージを送れるようになりました。

  • 画像・動画・カルーセル・リッチメッセージ: 原稿に @image・@video・@carousel・@richmsg と書くと、画像や横にめくれるカード、押せる範囲のある画像を送れます。カードにも画像を付けられます。素材は自分の Cloudflare（R2）に置き、配信の前に大きさや形を検問します。使うには R2 のバケットを1つ作ります（SETUP.md §10-15）
  • トークの画像: 管理画面のトークから画像を送れます。友だちから届いた画像も管理画面で見られます（届いてから180日で自動で消えます）
  • 分析: 管理画面の「LINE → 分析」で、どの入口（流入経路）の友だちが成果（指定したタグ）につながったか、どの配信の計測リンクが押されたか、友だちの増え方を、期間を切り替えて見られます（SETUP.md §10-16）
  • 試し送り: 原稿を自分にだけ1通送って見え方を確かめられます（AIに「この原稿を自分に試し送りして」と頼めば、SETUP.md §10-15 の手順で送ります）

予約ページ（個別相談・セミナー）　LINE の友だち・メールの読者・誰でもから、個別相談とセミナーの予約を受けられるようになりました。手順は SETUP.md §10-18

  • 予約ページ: 曜日ごとの受付時間と1枠の長さを設定に書くと、友だちが LINE の「予約する」ボタンから空き枠を選び、質問に答えて予約できます。1枠1人で、同時に押しても二重予約になりません
  • 変更・取り消し・リマインド: 締切までは友だちが自分で別の日時に変えたり取り消したりできます。前日と直前（設定で変えられます）に、日時と参加URLを LINE で知らせます
  • 管理画面: サイドバーの「予約」で予約の一覧・質問の答え・カレンダーに入れるファイル（.ics）・取り消し・枠を閉じる（休みの時間）ができます。新しい予約はいつもの通知にも届きます。セミナーは回ごとの参加者・CSV・カレンダー（.ics）も出せます
  • 誰でも申し込める予約ページ: 予約ページのURL（/r/キー）を LP や SNS に貼ると、名前とメールで申し込めます。確認メールのリンクで確定し、30分確認されなければ自動で取り消します。使うには Turnstile の公開鍵 TURNSTILE_SITE_KEY を設定に足します（SETUP.md §10-18）。メールの本文にも %booking:キー% で読者ごとの予約リンクを入れられます
  • 募集ページの雛形: 予約ページが、表紙・要点・こんな方に・当日の流れ・講師・参加した方の声・よくある質問・下に貼り付く「申し込む」の帯つきの募集ページになりました。中身は bookings.config.mjs の detail に書くだけ（書かなかった節は出ません）。書き方は SETUP.md §10-18
  • セミナー: 開催の回を並べて、回ごとに定員つきで受けられます。予約ページに内容・講師・場所・画像と「残り○席」を出し、満席の回はキャンセル待ちに並べられます（空きが出ると自動で繰り上がり、本人に知らせます）。書き方は SETUP.md §10-18
  • 設定: 新しい設定ファイル bookings.config.mjs（最初は空）が増えます。使うときは BOOKINGS に書きます（AIに頼めます）。名前とメールで誰でも申し込める入口は、Turnstile の鍵（TURNSTILE_SECRET と TURNSTILE_SITE_KEY）をそろえたときだけ開きます

LINE の A/Bテスト　LINE の文面を2通り試して、どちらが効くかを比べられるようになりました。手順は SETUP.md §10-17

  • A/Bテスト: ステップや一斉配信の原稿に @ab A / @ab B の節を書くと、友だちを半分ずつに分けて別の文面を送り、「LINE → 分析 → A/Bテスト」で押した人・ブロック・成果を比べられます。両方の文面に計測リンクを入れてください
  • 決め方: 押した人の率の差が偶然ではなさそうかを一言で出します（A・B 各30人から）。途中で何度も見て決めると偶然の差を選びやすいので、決める日（目安1週間後）を先に決めてください。勝った側だけを残して原稿を出し直すと終わります

Instagram自動応答（任意）

  • Instagram・Facebook・Threadsのアプリ内ブラウザから経路URLを開いた人は、LIFFを通さずLINEの友だち追加へ直接送ります（LINEログイン画面で止まるのを防ぐため）

メールの一斉配信　メールの一斉配信を、毎回の手作業なしで組めるようにしました。手順は SETUP.md §8「メールの一斉配信」

  • 宛先の絞り込み式: LINE と同じ AND/OR/NOT で、「この講座の読者のうち、〇〇の購入者と別の配信スタンドの読者を除く」のように書けます。従来の書き方もそのまま使えます
  • 名簿の取り込み: 他の配信スタンドから書き出した CSV を名簿にして、絞り込みに使えます（取り込みはAIに頼めます）。名簿が古い・空のときは送らずに止まります
  • 予定人数とテスト送信: 送る前に何人に届くかを確かめられ、管理画面のボタンかコマンドで自分宛てにテスト送信できます（件名に【テスト】・本番の集計に入りません）。設定 TEST_EMAILS に自分のアドレスを入れてください

押したら動くリンク・本文の分岐　メールでも、押した人に合わせて自動で動かせるようになりました。手順は SETUP.md §8「押したら動くリンク・本文の分岐・この講座だけ止める」

  • 押したら動くリンク: 本文のリンクを初めて押した人に、タグを付ける・外す、講座を始める・止める（別の講座へ移す）を自動で行えます。誰が押したかも記録します。リンクを開くだけの安全チェック（会社のメールなど）では動かない作りです（ページの中のプログラムまで実行する安全チェックでは、押したのと同じに数えられることがあります）。使うには鍵（MAIL_LINK_SECRET）を1つ入れます（AIに頼めます）
  • 本文の分岐: ステップメールの1通の中で、タグや購入の有無などで読者ごとに本文を出し分けられます。どれにも当てはまらない人には、その通を送らずに次の通へ進みます
  • この講座だけ止める: 講座ごとに「この講座だけ止める」リンクを付けられます。押した人も、ほかの講座と一斉配信はこれまでどおり受け取れます

購入で動く・人のタグ　購入で、タグ付け・メール講座の開始と停止・LINE のシナリオとメニューの切り替えが自動で動くようになりました（5分ごとの処理で反映。購入が続けて入ったときは次の回以降）。講座と LINE を動かすのは Stripe の決済の通知で入った購入だけで、CSV で取り込んだ購入にはタグだけ付きます。

  • 人のタグ: メールの読者と LINE の友だちが同じ人としてつながっていれば、どちらの絞り込みでも同じタグ（例: 〇〇講座の購入者）を使えます
  • 購入者自身の Stripe: 支払いリンクの決済を購入台帳に入れられます（支払いリンクと商品名の対応を設定に書きます）
  • 過去の購入者へのタグ: 人数を確かめてから、タグだけをまとめて付けられます（AIに頼めます）

管理画面

  • サイドバーとダッシュボードを整理しました。主の数字は既定のシナリオの読者に、宛先リスト全体は補助の1行にしています
  • 計算がずれていたCVRの表示をやめました（注文は全販路の数で、教材クリックで割ると100%を超えていました）。開封率は「届いた通数のうち開封された通数」（ステップ配信＋一斉配信・直近30日）で数えるように直しました

メール・全体（配信の土台）

  • Cloudflareは有料のWorkers Paid（月$5）が必須になりました。無料プランは1回の処理で使えるデータベース問い合わせが50件までで、朝の配信時刻に読者が3人以上重なると処理が途中で止まり、配信が遅れたり、v0.8以前では同じメールが何度も届いたりすることがありました。Workers Paidへ切り替えたうえで、更新時にAIが設定の1回あたりの送信数（SEND_BATCH_MAX）を50へ上げます（1日14,400通まで送れます）
  • 配信が遅れたとき、遅れた分が数分おきに続けて届いてしまう問題を修正しました（テスター報告に対応）。遅れた便のあとは次の配信時刻まで間をあけ、同じ講座は1人に1日1通までに抑えます
  • 講座（読者リスト）を複数持てるようになりました。同じ読者が複数の講座に登録でき、講座ごとに確認メールで本人確認します。手順はSETUP.md §8
  • 2つの講座へ続けて登録したとき、2件目の確認メールが届かないことがある問題を修正（テスター報告に対応）
  • 購入者リストのCSV取り込みを同梱しました（MyASP・UTAGE・Stripe・Brainなどの書き出しをそのまま読めます。メールは送られません）
  • 消した原稿を配信DBから安全に片付ける機能を追加（一覧を確認してから停止。まだ届く予定の読者がいる便は止めません）
  • Codexでも導入・運用できるよう、入口の案内（AGENTS.md）を同梱しました
  • 手順書に、テスターの方が実際に詰まった点を追記（CloudflareのDNSは「DNSのみ」に・Resend無料プランは1ドメイン・自サイトのCSP設定・確認メールの講座名の出どころ・更新時に自分の改修を消さない手順）
  • 配布ファイルの名前に版番号が入るようになりました（例: rondo-dist-v1.0.0.zip）
  • 管理画面（分析・計器盤）を開いたときや毎晩の休眠判定で、CloudflareのD1の読み取り量が大きく膨らむ問題を修正しました（1回で数千万行を読むことがありました）。データベースに検索用の索引を追加します。更新手順のmigration適用で自動的に入ります
  • LINEの配信が止まった後に再開したとき、遅れた分が数分おきに続けて届いてしまう問題を修正しました（メールと同じく、次の配信時刻まで間をあけます）
  • 通信が途切れたときなどに、同じメール・LINEが二重に届く可能性を大幅に減らしました（送信サービスの重複防止キーを使い、結果が分からない送信は同じ内容でしか送り直しません。24時間たっても決着しないものは自動では送らず、管理画面の打ち止め一覧でお知らせします）
  • 再試行の上限に達した送信が、まれに処理されないまま残り続けることがある問題を修正しました
  • DiscordやFiNANCiEの集計に失敗したとき、5分おきに最初からやり直していたのを、間隔をあけて取り直すようにしました
  • LPの計測タグ（ヒートマップ）の受け口に上限を設けました（無料プランのデータベース書き込み枠を計測だけで使い切らないように。上限は HEAT_DAILY_WRITE_MAX で変えられます）
  • 顧客スコア: 顧客が数千人いると、その日最初の定時処理（5分ごと）で再採点の書き込みが1回の上限（Cloudflare D1 の1回あたり1,000件）を超え、同じ回の後ろの処理が失敗することがありました。再採点は配信の後に残った枠の中で少しずつ進め、何回かの定時処理で全員を採点し終えるようにしました（3,000人なら配信の無い時間帯で40分ほど）。採点の基準は前と同じです（採点の途中で購入の訂正や名寄せがあった人は、翌日の採点でそろいます）。設定の変更は要りません
